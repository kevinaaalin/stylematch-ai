# PART A — Software Design Foundation

## Chapter 1. Purpose

本文件定義 TIGI 各軟體元件（Software Components）的內部設計原則、模組拆分、責任邊界、介面設計與相依關係。

本文件描述「如何設計（How to Design）」，不描述業務需求（BRS）、整體架構（SAD）或治理規則（TGS）。

---

## Chapter 2. Software Design Principles

### SDP-01 Single Responsibility

每個 Software Module 僅負責一項明確職責。

### SDP-02 High Cohesion

同一模組內功能應高度相關。

### SDP-03 Low Coupling

模組間應透過正式介面互動，避免直接依賴內部實作。

### SDP-04 Interface First

所有對外能力均須定義正式介面，再進行實作。

### SDP-05 Dependency Inversion

高階模組不得依賴低階實作，而應依賴抽象介面。

### SDP-06 Testability

所有模組應具備可單元測試、整合測試與驗收測試能力。

### SDP-07 Governance Compliance

任何模組不得繞過 Governance Core 或自行變更案件治理狀態。

# Chapter 4. Module Responsibility Matrix

建立模組責任矩陣：

| Module | Responsibility | Not Responsible |
|--------|----------------|-----------------|
| Case Module | 案件資料管理 | 狀態控制 |
| Workflow Module | 流程協調 | Gate 驗證 |
| State Module | 狀態轉換 | 業務規則 |
| Gate Module | Gate 驗證 | 資料維護 |
| Evidence Module | 證據管理 | 流程控制 |
| Audit Module | 稽核紀錄 | 權限判定 |
| AI Agent Module | AI 推論 | 治理決策 |

# Chapter 5. Internal Design Rules

所有模組必須遵循：

- 模組不可直接操作其他模組資料。
- 共用功能應抽象化為 Shared Component。
- 所有跨模組呼叫均須保留 Trace ID。
- 發生錯誤須回傳標準錯誤格式。
- 所有治理相關操作均須經 Governance Core。

---

# Chapter 6. Layered Design

軟體內部採四層設計：

1. Interface Layer（API／事件介面）
2. Application Layer（應用協調）
3. Domain Layer（核心業務邏輯）
4. Infrastructure Layer（資料存取與外部整合）

各層不得跨越相鄰層直接依賴。
