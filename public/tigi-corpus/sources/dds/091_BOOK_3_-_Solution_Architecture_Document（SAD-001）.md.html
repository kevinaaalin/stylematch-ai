# Chapter 8. Application Architecture Principles

所有 Application Component 必須遵循：

### AA-01 Single Responsibility

每一個 Service 僅負責一種業務能力。

不得混合多個 Business Capability。

---

### AA-02 Stateless Service

Application Service 不保存 Session 狀態。

所有案件狀態由 Governance Core 管理。

---

### AA-03 API Driven

所有 Service 間互動均透過正式 API／事件介面。

不得直接存取其他 Service 的內部邏輯。

---

### AA-04 Independent Deployment

每個 Service 應具備獨立部署能力。

---

### AA-05 Governance Compliance

所有 Service 必須遵循：

- Governance Core
- State Machine
- Gate Engine
- Checklist Engine
- Audit Trail

不得自行改變案件狀態。

# Chapter 10. Component Responsibilities

每個 Component 皆定義唯一責任。

例如：

### AC-001 Case Service

負責：

- 建立案件
- 更新案件基本資料
- 查詢案件
- 結案

不得：

- 控制流程
- 驗證 Gate
- 修改 Checklist

上述能力由其他 Component 負責。

---

### AC-004 Gate Engine

負責：

- Gate 驗證
- Gate 規則執行
- Gate 通過判定

不得：

- 修改 Case
- 執行付款
- 建立文件

---

### AC-006 Evidence Service

負責：

- 上傳 Evidence
- 驗證 Evidence
- Evidence 版本管理
- Evidence 查詢

不得：

- 驗收
- 合約管理
- Workflow 控制

---

### AC-012 PGP Engine

負責：

- 建立 PGP
- 封裝治理資訊
- PGP 驗證
- PGP 匯出

不得：

- 控制 Workflow
- 修改案件
- 執行 Gate

---

# Chapter 11. Component Interaction Rules

所有 Component 必須遵循以下互動規則：

- 僅透過公開介面互動。
- 不得直接存取其他 Component 的資料庫。
- 不得跨越 Governance Core 修改狀態。
- 所有重要事件須產生 Audit Record。
- 所有跨 Component 呼叫均須具備 Trace ID。

---

# Chapter 12. Architecture Dependency

建立正式依賴方向：

```
Experience Layer
        │
Application Services
        │
Governance Core
        │
AI Platform
        │
Data Services
        │
Infrastructure
```

依賴方向僅能由上而下。

禁止反向依賴。

禁止跨層直接呼叫。

---

# Chapter 13. Cross Reference

Application Component 與其他文件建立正式對應：

- **BRS-001**：需求來源
- **TGS-001**：治理規則
- **SDD-001**：元件內部設計
- **DDS-001**：資料模型
- **OpenAPI-001**：介面規格
- **GS-01～GS-24**：治理標準

任何 Component 的修改，均須同步更新對應文件，並維持追溯鏈完整。
